# API 设计约定（测试用）

> 适用于 `design_api`（产出 API 设计）与 `implement_code`（按契约落地）。

## 硬性要求

- 每个接口写全三件事：**请求**（路径/查询/请求体字段表）、**响应**（示例 JSON + 字段表）、**错误码**。
- 字段命名对齐技术方案「术语清单」的英文命名，同一概念不许多种叫法。
- 示例 JSON 字段完整，前端可直接照此 mock。
- 禁止「同上」「略」「按需添加」。

## REST

- 资源路径用名词复数或约定好的单数集合名；动词放在 HTTP 方法上。
- 成功响应 JSON 结构稳定；错误返回 `{ "error": "..." }` 与合适 HTTP 状态码。
- 列表接口必须有分页或上限，返回结构包含数据与总数。

## 兼容

- 新增字段默认可选；删改字段需版本说明或迁移期。
- 存量调用方受影响时，写清灰度或版本过渡方式。

## Web 操作台专用

- `/api/*` 与静态 SPA 分离；非 API 路径 fallback 到 `index.html`。
- 配置类数据持久化在 `.dev-workflow/web-ui/`，便于本地调试。

## 文档

- 对外接口在 README 或 OpenAPI 片段中留最小示例。
