# 编码风格（测试用）

## 通用

- 优先小函数、单一职责；单文件不宜过长。
- 新增逻辑复用现有工具与模式，避免重复造轮子。
- 错误信息要对运维/开发可读，带必要上下文。

## Python

- 类型注解与 docstring 在公共 API 上必填。
- 日志用 `logging`，禁止随意 `print` 进生产路径。

## 前端（Vue / TS）

- 组合式 API + 与 Vben 现有目录结构保持一致。
- 样式优先 Tailwind / 项目 token，少写一次性 magic number。

## 提交前

- 只改与需求相关的文件；格式化与 lint 通过后再提交。
