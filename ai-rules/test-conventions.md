# 测试约定（测试用）

## 分层

- 单元测试：纯逻辑、无真实网络/磁盘副作用（可用 mock）。
- 集成测试：API、持久化、关键路径端到端。
- UI：关键流程手工或 E2E 清单写在测试用例文档中。

## 命名与结构

- 测试名描述「场景 + 期望」，例如 `test_bind_rule_set_updates_node_rules`。
- 每个 Bug 修复尽量带回归用例。

## 数据

- 测试数据与生产配置隔离；勿把密钥写进仓库。
- 临时目录用 fixture 或 `.dev-workflow` 下约定路径。

## 通过标准

- 新功能需说明如何验证；改 API 需同步更新调用方或文档。
