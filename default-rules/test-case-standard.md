# 测试用例规约（旅程式 E2E）

> 适用节点：`design_test_cases` `review_plan_and_tests` `verify_tests`
> 来源：skill://test-case-rule（详见 `ai-reles/test-case-rule.md`）
> 定级：【强制】必须遵守 / 【推荐】建议 / 【参考】可选

## 视角【强制】
- **旅程优先**：一条用例 = 一条用户完整业务链（从入口到闭环），串联**多页/多模块/多角色/多系统**。
- 不是穷举某模块内部所有分支（分支穷举交功能/API/单测用例）。
- `design_test_cases` 节点只产出 `TC-UNIT-*` / `TC-API-*`（旅程/场景用于梳理覆盖）；E2E 由 `verify_tests` 补 `TC-E2E-*`。

## 用例结构【强制】
| 字段 | 要求 |
|---|---|
| 场景ID | `<J>-<HN|AL|EX>-<序号>`（HN 基本流 / AL 备选流 / EX 异常流） |
| 前置条件 | 明确（角色、系统状态、数据） |
| 步骤链 | 跨模块/角色的逐步动作（如 申请→冻结→审核→出款→到账） |
| 预期结果 | **可断言**（状态、字段、闭环终态） |
| 测试数据 | 可造、敏感字段掩码；引用 `api-design` 的 mock JSON |

## 关键覆盖【推荐】
- 每个「用户目标」到闭环；每个角色至少出现一条旅程。
- 关键备选流/异常流：拒绝/失败/超时/并发/幂等。
- 跨系统交互（RPC/三方/双写）在旅程中体现。

## 反模式
| 反模式 | 正确做法 |
|---|---|
| 按功能模块列用例 | 按用户旅程列用例 |
| 穷举某模块所有输入边界 | 只测旅程主链路+关键分支 |
| 一条用例只断言一个接口 | 串联多步到闭环 |
| 场景到半路截止 | 到达成功/明确失败终态 |
